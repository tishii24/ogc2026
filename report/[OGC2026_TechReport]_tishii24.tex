\title{OGC2026 Technical Report}
\maketitle

\begin{abstract}
This report presents a heuristic for a block scheduling problem that simultaneously involves temporal constraints and geometric constraints on multilayer polygons. For each block, the problem requires determining its bay, orientation, coordinates, entry time, and exit time; in particular, crane accessibility for entry and exit strongly couples placement and time. The core of the proposed method consists of abstract preoptimization, which relaxes the exact geometric constraints into time-indexed area-capacity constraints, and rolling-horizon optimization following the admission order obtained from the abstract solution. In each horizon, a feasible solution is constructed by greedy insertion that integrates a spatial sweep with forbidden entry-time intervals, and is improved by parallel simulated annealing with several neighborhoods, including large reconstruction that removes and reinserts multiple blocks. Because it is difficult to move from a dense packing to a structurally different arrangement using local changes alone, the method emphasizes obtaining a good admission order in advance and optimizing every block at least once while it is near the end of the partial schedule.
\end{abstract}

\section{Introduction}

\subsection{Challenge Problem \& Main Difficulties}

For every block $i$, we determine its assigned bay $b_i$, orientation $o_i$, coordinates $(x_i,y_i)$, entry time $e_i$, and exit time $q_i$. The temporal constraints are
\begin{equation}
e_i\ge R_i,\qquad q_i-e_i\ge P_i.
\end{equation}
Blocks occupying the same bay at the same time must not overlap at layers of the same height. Moreover, during an ENTRY or EXIT operation, vertically moving the target block must not collide with layers of other blocks at the same or a greater height than each target layer. Consequently, even a statically non-overlapping placement may be infeasible for crane operations.

The objective is the weighted sum of total tardiness $Z_1$, workload imbalance among bays $Z_2$, and bay-preference penalty $Z_3$:
\begin{equation}
F=w_1Z_1+w_2Z_2+w_3Z_3.
\end{equation}
In particular,
\begin{equation}
Z_1=\sum_i\max(0,q_i-D_i),\qquad
Z_3=\sum_i(S_i^{\max}-S_{i,b_i}),
\end{equation}
so $Z_1$ and $Z_3$ decompose into block-wise contributions. Whether these values can be realized, however, depends on the placements and residence intervals of other blocks.

The primary difficulty is the rigidity of the search space. Once a bay becomes densely packed, the space created by moving a single block is often insufficient to improve another block; changing the packing structure requires coordinated changes to several blocks. Furthermore, moving an early block changes its collision relationships and crane ordering with many later blocks. Search performance therefore depends strongly on the initial solution, especially the order in which blocks are admitted to the geometric schedule.

\subsection{Contributions}

The main contributions of this report are as follows.
\begin{itemize}
    \item We introduce abstract preoptimization that relaxes multilayer polygon constraints into time-indexed area-capacity constraints and obtains an admission order from the bay assignment and entry time of every block.
    \item We construct a rolling-horizon framework that expands partial problems according to the abstract admission order, allowing every block to be optimized once while it is at the flexible end of the partial schedule.
    \item We develop greedy insertion that jointly searches space and time by combining an $x$-direction sweep for multilayer collisions, based on Minkowski differences, with forbidden entry-time intervals induced by crane constraints.
    \item We combine small neighborhoods with large reconstruction, which structurally selects and reinserts multiple related blocks, within parallel simulated annealing.
\end{itemize}

\section{Algorithm Description}

\subsection{Overall Algorithm Framework}

\subsubsection{Key findings and design rationale.}
In total tardiness, every unit of block tardiness has the same weight regardless of block size. Given one large block and several small blocks with similar ENTRY/EXIT conditions, processing the small blocks first may therefore reduce $Z_1$. In contrast, large blocks are easier to insert while ample free space remains. Thus, an order favorable for tardiness does not necessarily coincide with one favorable for packability. A simple release-time or due-date order cannot simultaneously account for block size, processing time, bay capacity, bay preference, and competition with other blocks.

Rolling-horizon optimization requires an order in which blocks are introduced into its partial problems. We first solve a preoptimization problem that omits exact coordinates, obtaining globally desirable entry times $\hat e_i$, and use their ascending order as the admission order. Abstract preoptimization therefore determines which blocks should be admitted first, whereas rolling-horizon optimization determines how that order is converted into an exact geometric schedule.

Rolling-horizon optimization itself has four advantages. First, each stage is a partial problem with a limited number of admitted blocks. Second, $Z_1$ and $Z_3$, which are dominant in many cases, are block-wise additive; improving them in a partial problem is therefore aligned with improving the full objective. Third, blocks near the end of a schedule have no later blocks and are consequently easier to move in time and space. Because each block is once newly admitted at the end of a horizon, every block receives an opportunity to be optimized with relatively high freedom. Fourth, neighborhood evaluation becomes more expensive as the number of admitted blocks grows, so the smaller early problems allow more iterations per unit time. Blocks from previous horizons are not frozen; all admitted blocks remain in the search to permit corrections after later blocks are added.

In a dense schedule, single-block neighborhoods such as Shift and Move are insufficient to change the packing structure. We therefore use large reconstruction, which removes several related blocks and reinserts them in a different order. The three key ideas consequently have complementary roles: abstract preoptimization supplies a global admission order, rolling-horizon optimization creates small and flexible subproblems, and large reconstruction makes substantial structural changes within each subproblem.

\subsubsection{Solution procedure.}
The complete procedure is as follows.
\begin{enumerate}
    \item Precompute the bounding box of every orientation, feasible placement ranges in each bay, neighboring orientations, swap candidates, and collision information.
    \item Solve the area-capacity relaxation and obtain a bay $\hat b_i$ and entry time $\hat e_i$ for every block.
    \item Sort the blocks lexicographically by $(\hat e_i,D_i,i)$ and construct horizons without splitting blocks having the same $\hat e_i$.
    \item Greedily insert the newly admitted blocks under the exact geometric constraints and improve all admitted blocks by simulated annealing.
    \item In the final horizon, after all blocks have been admitted, perform final improvement using the complete objective containing $Z_1$, $Z_2$, and $Z_3$.
\end{enumerate}

\subsection{Key Ideas that Succeeded}

\subsubsection{Abstract preoptimization.}
For orientation $o$ of block $i$, let $A^{\mathrm{union}}_{io}$ be the area of the union of all layers, $A^{\mathrm{bbox}}_{io}$ be the area of its bounding box, and $L_{io}$ be the perimeter of the union. If orientation $o$ fits in bay $j$, its approximate occupancy is
\begin{equation}
a_{ijo}=A^{\mathrm{union}}_{io}
+\alpha\left(A^{\mathrm{bbox}}_{io}-A^{\mathrm{union}}_{io}\right)
+\beta L_{io}.
\end{equation}
We define $a_{ij}$ as the minimum value over orientations that fit in bay $j$. The first term represents the actual occupied area, the second approximates unusable space around concave or elongated shapes, and the third compensates for packing difficulty caused by a complex boundary.

Let $C_j$ be the effective capacity of bay $j$. The abstract schedule must satisfy
\begin{equation}
\sum_{i:\,\hat e_i\le t<\hat e_i+P_i,\,\hat b_i=j}a_{ij}\le C_j
\end{equation}
at every time. An abstract state stores only $(\hat b_i,\hat e_i)$ for each block and does not store its exact orientation or coordinates. Its objective consists of $Z_1$, $Z_2$, and $Z_3$ evaluated on the abstract schedule, plus a congestion penalty. The implementation sums products of the occupancy ratios of simultaneously resident block pairs over time. This discourages highly congested abstract schedules that satisfy the area capacity but are difficult to convert into exact placements.

Initial states are built greedily from multiple randomized block orders. Each order combines workload, the product of area and processing time, the spread of bay preferences, the limit time defined as due date minus processing time, slack, and a random component. For each block, the earliest capacity-feasible time is found in every eligible bay, and the candidate minimizing the incremental $Z_1$, $Z_2$, $Z_3$, and congestion is selected. The state is then improved by simulated annealing using relocate, swap, and multi-block reconstruction neighborhoods.

\subsubsection{Rolling-horizon geometric optimization.}
Blocks are sorted by $(\hat e_i,D_i,i)$, and horizons are formed with a prescribed block count. Blocks with the same $\hat e_i$ at a horizon boundary are included in the same horizon. At each horizon, newly admitted blocks are first inserted using $\hat e_i$ as their reference entry time. Simulated annealing is then applied not only to the new blocks but to all blocks admitted so far. Unlike a freezing-type rolling horizon, earlier decisions can therefore be revised in response to later admissions. Rolling-horizon decomposition has also been applied to large tardiness scheduling problems\cite{singer2001}.

Because $Z_2$ is not meaningful until the bay assignments of all blocks are present, its weight is set to zero in intermediate horizons. The official $w_2$ is enabled only in the final horizon. Search time is allocated with weights proportional to a power of the number of admitted blocks, reserving more time for the larger late-stage problems.

\subsubsection{Greedy geometric insertion and collision detection.}
Greedy insertion enumerates bays, orientations, and integer $y$ coordinates, while sweeping in the $x$ direction through collision events. A candidate $s$ is compared primarily by
\begin{equation}
\Delta F(s)=w_1T_i(s)+w_2\Delta Z_2(s)
+w_3(S_i^{\max}-S_{i,b_i(s)}).
\end{equation}
Among candidates tied with the best objective value, an earlier entry time and placement near a bay corner are preferred. The default anchor is the bottom-left corner, but one of the other three corners is selected with a small probability to generate different packing structures.

For collision detection, each nonconvex layer is decomposed into convex polygons by ear clipping. For two convex polygons $A$ and $B$, a collision occurs when their relative displacement $(\Delta x,\Delta y)$ belongs to
\begin{equation}
A\oplus(-B)=\{a-b\mid a\in A,\ b\in B\}\cite{ghosh1993}.
\end{equation}
This region is horizontally sliced at every integer $\Delta y$ and converted into intervals of forbidden integer $\Delta x$. This relative-placement representation is analogous to the no-fit polygon used in irregular packing\cite{burke2008}. A small margin prevents missed collisions due to numerical errors, and overlapping or adjacent intervals in the same row are merged. For crane constraints, forbidden regions are united for every moving layer $k$ and fixed layer $l\ge k$. Because crane obstruction is directional, the two directions of every orientation pair are stored separately. The collision grid is lazily constructed on first use and then cached.

\paragraph{Joint spatial-temporal sweep.}
The distinguishing feature of the insertion procedure is that spatial and temporal searches are not separated. For every existing block, the algorithm separately tracks whether the new block is obstructed by the existing block and whether the existing block is obstructed by the new block. Endpoints of forbidden $x$ intervals are treated as events, and these two directional states are updated during the $x$ sweep. From the current state and the residence interval of the existing block, the forbidden entry times of the new block can be represented by at most two intervals. All active forbidden intervals at the current coordinates are merged to find the earliest feasible entry time in the search range. Hence, the full schedule need not be revalidated at every coordinate and every day, and the running time does not directly depend on the time horizon.

Let $n_j$ be the number of blocks already placed in bay $j$, let $W_j$ and $H_j$ be its width and height, and let $O_i$ be the number of orientations of the inserted block. Treating the number of collision intervals per block pair as constant, event generation and counting sort for one $(o,y)$ require $O(n_j+W_j)$ time. A conservative bound including scans of forbidden time intervals at candidate positions is $O(W_j+n_j^2)$. The approximate worst-case complexity of inserting one block is therefore
\begin{equation}
O\left(\sum_j O_iH_j(W_j+n_j^2)\right).
\end{equation}

\subsubsection{Simulated annealing and large reconstruction.}
The local search is based on simulated annealing\cite{kirkpatrick1983} and uses five neighborhood types: Large Reconstruction, Shift, Move, Rotate, and Swap. Shift scans nearby $y$ coordinates while retaining the bay and orientation. Rotate changes to a geometrically similar orientation precomputed in advance. Move primarily selects a relatively small block and redetermines its bay, orientation, position, and time by greedy insertion. Swap exchanges the locations of two blocks with similar area and shape and reinserts both.

Large reconstruction selects multiple seeds using three methods: badness, fluidity, and random selection. Badness evaluates tardiness, preference penalty, and membership in the bay with the heaviest workload. Fluidity favors blocks with large slack and a small spread of bay preferences, which are easier to move. Blocks in the same bay as each seed are ordered by
\begin{equation}
d(i,s)=\lambda_x(x_i-x_s)^2+\lambda_y(y_i-y_s)^2
+\lambda_t(e_i-e_s)^2,
\end{equation}
and nearby blocks are removed together. Multiple seeds make it possible to change several local structures in one move. The reinsertion order is determined from a weighted combination of workload, volume, preference spread, limit time, slack, current penalty, and randomness. These weights are randomized for every attempt, allowing the search to revisit the trade-off between tardiness and packability without being restricted to a fixed size or due-date order. Large reconstruction in abstract preoptimization is simpler because the abstract state has no coordinates.

Simulated annealing is executed by multiple workers in parallel. Each worker updates a shared best state and periodically imports a sufficiently better shared solution. During stagnation, the worker returns to its best state and reheats by temporarily increasing its temperature. Distinct temperature ranges are used when positive tardiness remains and after tardiness reaches zero: the former handles larger changes in $Z_1$, while the latter focuses on finer improvements, primarily to $Z_3$. A tabu set of schedule hashes suppresses short-term revisits to identical states.

\subsection{Key Ideas that Failed}

Beam-search reconstruction attempted to reuse block-insertion results relative to the same base schedule across multiple search states, thereby exploring reinsertion orders at lower computational cost. However, exploring diverse placement states proved more important than reusing insertion results, and the method was discarded.

Multi-stage optimization, which optimized tardiness, preference, and workload imbalance in separate stages, did not show a significant advantage over the standard search. We also tested adaptive annealing that derived its temperature from observed objective differences and a blocker-aware neighborhood that explicitly removed blocks obstructing crane operations. Both ideas appeared promising, but obtaining parameter settings that worked consistently across instances was difficult.

\subsection{Further Improvement Plan}

For abstract preoptimization, we plan to improve approximate occupancy and congestion so that the gap between abstract schedules and exact placements is reduced. For rolling-horizon optimization, horizon size and search-time allocation could be adapted to each instance. We also plan to include the ordering of ENTRY/EXIT operations at the same time and temporal-order changes produced by modifying exit times. For large reconstruction, blocker dependencies could be used more directly in selecting blocks for removal.

For simulated annealing, in addition to revisiting adaptive temperature control based on objective differences and acceptance ratios, we plan to introduce a more systematic parallel scheme. Workers would specialize in different temperature ranges or neighborhood compositions and periodically exchange states, explicitly separating structural changes by high-temperature workers from local improvement by low-temperature workers.

\section{Implementation Details}
\label{sec:implementation}

The solver is implemented in Rust and parallelized with Rayon. Convex decompositions, bounding boxes, feasible placement ranges in bays, orientation neighbors, and swap candidates are precomputed. Collision grids for block and orientation pairs are built on demand and shared throughout the subsequent search. The placement sweep processes only endpoints of forbidden $x$ intervals and uses counting sort and bitsets to maintain active time intervals.

The time limit is divided between abstract preoptimization and rolling horizon optimization. In the latter phase, the deadline of each horizon is computed from the sizes of the remaining horizons. The current shared best solution is emitted periodically during the search. EXIT operations are added to the output before ENTRY operations, ensuring that every EXIT precedes every ENTRY at the same time.

A Python wrapper surrounds the Rust solver. It deduplicates emitted candidates, checks them in objective-value order, and independently validates assignments, temporal constraints, bay containment, multilayer collisions, and crane operations using Shapely. If the best candidate is infeasible, the wrapper falls back to the next previously emitted feasible candidate. Time for validation and returning the result is reserved in advance from the solver time limit.
