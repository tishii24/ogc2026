## Abstract

- 対象問題
  - 複数のベイへのブロック割当、向きと二次元位置、搬入・搬出時刻を同時に決定する時空間スケジューリング問題
  - 多層多角形の衝突、ベイ境界、クレーンによる垂直搬送可能性をすべて満たす必要がある
- 提案手法の概要
  - 幾何制約を面積容量へ緩和した抽象スケジュールを先に最適化する
  - 抽象解から得たベイ割当と時刻順序を利用して、実行可能な幾何解を構築する
  - Large Neighborhood Search を含む複数近傍の並列 Simulated Annealing で解を改善する
  - 搬送制約を考慮した配置可能時刻を高速に走査する
- 主な実装上の特徴
  - 多角形対の衝突関係を相対座標グリッドとして遅延計算・キャッシュする
  - x 座標のイベント走査と禁止時間区間の統合により、位置と時刻を同時に探索する
  - 複数 worker が探索し、共有最良解を交換する
- 結果
  - `[集計・保留]` training データに対する最終結果と主要改善の要約を記載する

## 1. Introduction

### 1.1 Challenge Problem & Main Difficulties

- 問題の概要
  - 各ブロックについて、ベイ、向き、整数座標、ENTRY 時刻、EXIT 時刻を決定する
  - ブロックは滞在区間 `[ENTRY, EXIT)` でベイを占有する
  - 同じ高さのレイヤー間の衝突を避ける必要がある
  - ENTRY/EXIT 時には、対象ブロックの各レイヤーが他ブロックの同じ高さ以上のレイヤーに妨害されてはならない
- 目的関数
  - `Z1`: 総遅れ
  - `Z2`: ベイ面積で正規化した作業量の最大不均衡
  - `Z3`: 選択したベイに対する選好ペナルティ
  - 与えられた重み `w1`, `w2`, `w3` による加重和を最小化する
- 主な難しさ
  - ベイ割当、幾何配置、スケジューリングが相互依存し、独立に最適化しにくい
  - 同一位置関係でも、滞在区間と操作順によって実行可能性が変わる
  - 非凸かつ多層の多角形について、多数回の衝突・クレーン判定が必要になる
  - `Z1`, `Z2`, `Z3` の重要度がインスタンスの重みにより変化する
  - 良いベイ割当・時刻割当が得られても、それを実際の幾何配置へ変換すると解品質が失われ得る

### 1.2 Contributions

- 二段階の初期解構築
  - 幾何制約を面積容量へ緩和した抽象問題を先に解き、ベイ割当と ENTRY 時刻を決める
  - 抽象解からヒューリスティックな先行関係を抽出し、幾何的に実行可能な解へ再構築する
- 配置と時刻の統合走査
  - 固定したベイ・向き・y 座標について、x 座標をイベント走査する
  - 各 x 区間でクレーン操作が禁止される時間区間を求め、最早の実行可能 ENTRY 時刻を選ぶ
- 複合的な Large Neighborhood Search
  - 悪いブロック、移動自由度の高いブロック、ランダムなブロックを seed として選ぶ
  - 時空間的に近いブロック群をまとめて除去し、重み付き優先度で順番を変えて再挿入する
- 複数の局所近傍
  - Shift、Move、Rotate、Swap と Large Reconstruct を組み合わせる
  - 選好・遅れ・作業量不均衡を考慮して候補を選ぶ
- 並列探索と高速衝突判定
  - Rayon により複数 worker の SA を並列実行し、共有最良解を交換する
  - ブロック対・向き対のクレーン衝突グリッドを遅延構築して再利用する
- `[要確認]` 各 contribution の相対的な効果は、後で実験結果または開発履歴に基づいて表現を調整する

## 2. Algorithm Description

### 2.1 Overall Algorithm Framework

- Stage 0: 幾何情報の前計算
  - 各ブロック・向きの bounding box とベイ内に収まる整数座標範囲を計算する
  - ベイ選好順、向きの bounding-box 面積順、類似向き、Swap 候補を前計算する
  - 各ブロックの最大 footprint 面積と、最良・次善ベイの選好差を計算する
  - 衝突グリッド本体は必要になった向き対だけを遅延構築する
- Stage 1: 抽象スケジュールの構築と最適化
  - 各向きのレイヤー和集合面積、bounding-box 面積、周長から近似占有面積を計算する
  - 近似占有面積
    - `union_area + alpha * (bbox_area - union_area) + beta * perimeter`
  - 各ベイを時間方向の面積容量として扱い、ブロックのベイと ENTRY 時刻を決定する
  - 初期状態は優先度をランダム化した複数の貪欲構築から選ぶ
  - Relocate、Swap、Large Reconstruct 近傍による並列 SA で抽象解を改善する
  - 公式目的関数に加え、同時刻の混雑を避ける補助ペナルティを探索時だけ加える
- Stage 2: 抽象解から幾何的実行可能解を構築
  - 抽象解で同じベイに割り当てられ、時間的に十分離れたブロック対から先行関係を作る
  - ベイごとに先行関係を満たす複数の topological order を生成する
  - workload、footprint 面積と処理時間からなる volume、選好差、納期の厳しさ、slack、ランダム値で挿入順を評価する
  - 各順序についてブロックを貪欲挿入し、ベイごとに総遅れが最小の実行可能スケジュールを採用する
- Stage 3: 制約付き global SA
  - 抽象解由来の先行関係を保持したまま、実配置を改善する
  - 抽象解の構造を急に壊さず、実行可能な幾何解の近傍を探索するための導入フェーズとする
- Stage 4: 制約なし global SA
  - 先行関係を外し、すべての近傍を用いてより広い解空間を探索する
  - 遅れが残る場合と遅れがゼロの場合で温度設定を切り替える
- Stage 5: 解の出力
  - 改善中の候補解を一定間隔で逐次出力する
  - 最終的に EXIT 操作を先に、ENTRY 操作を後にまとめた日別操作列へ変換する
  - Python wrapper 側で候補をスコア順に確認し、実行可能な候補を返す
- `[図・保留]` 上記 Stage 0–5 のフローチャートを作成する
- `[図・保留]` 抽象スケジュールから幾何配置へ変換する概念図を作成する

### 2.2 Key Ideas that Succeeded

- 抽象最適化による探索空間の分解
  - 最初から多角形配置を含む完全問題を解く代わりに、近似占有面積による容量制約でベイと時刻を先に探索する
  - `Z1`, `Z2`, `Z3` を抽象段階でも直接評価し、幾何探索の初期方向を与える
  - 混雑ペナルティにより、面積容量の上限を満たすだけでなく、余裕を持つ抽象解を優先する
- 抽象解由来のヒューリスティック先行関係
  - 抽象解で時間的に分離された同一ベイのブロック対だけを先行制約として採用する
  - 初期構築と global SA 前半で探索を安定させ、後半では制約を外して局所最適からの脱出を許す
- クレーン制約を含む配置可能時刻の直接計算
  - ブロック対の各レイヤーを凸分解し、Minkowski 差に基づいて相対整数座標の衝突区間を生成する
  - 新規ブロックと既存ブロックの双方のクレーン方向を考慮する
  - x 方向の衝突状態が変わる座標だけをイベント化し、同じ禁止時間集合を持つ x 範囲をまとめて処理する
  - 禁止区間を統合し、release time と先行制約を満たす最初の ENTRY 時刻を求める
- 問題構造を使った Large Reconstruct
  - 除去数を範囲から確率的に選び、小規模変更と大規模変更を混在させる
  - seed 選択を badness、fluidity、random の混合とする
  - seed の周囲から、同一ベイ内で x・y・ENTRY 時刻が近いブロックをまとめて除去する
  - 再挿入順の重みを試行ごとに変え、多様な順序を探索する
  - 現在の `w1 Z1 + w3 Z3` 寄与が大きいブロックや、slack が小さいブロックを優先できる
  - 再構築中に確定済みの `Z1 + Z3` 下界が受理可能値を超えた場合は早期終了する
- 目的別の局所近傍
  - Shift: 同じベイ・向きのまま y を変更し、より早い実行可能時刻を探す
  - Rotate: bounding box が近い向きと周辺 y 座標を試す
  - Move: 小さい footprint の候補からコスト寄与の大きいブロックを選び、ベイを含めて再挿入する
  - Swap: footprint が近いブロック対について位置・ベイを交換する
- 並列 SA
  - 4 worker が異なる乱数列で同じ初期解から探索する
  - worker ごとの局所最良と全 worker の共有最良を管理する
  - 一定のスコア差がある場合に共有最良解を取り込み、探索の進展を伝播する
  - schedule hash による tabu list で短い巡回を抑える
- `[集計・保留]` 各段階の objective、`Z1`, `Z2`, `Z3` の変化を確認し、どのアイデアを「成功」と断定できるか決める
- `[集計・保留]` 近傍別の selected / succeeded / improved / accepted / CPU time ログを集計する

### 2.3 Key Ideas that Failed or Were Deferred

- Beam Large Reconstruct
  - 固定ブロックに対する挿入候補を前計算し、除去ブロックの再挿入をビームサーチする実装が存在する
  - 現行パラメータでは重みが `0.0` であり、使用していない
  - 候補数と計算時間の負担、および候補生成の偏りを調整してから再導入する予定
  - 定量的な失敗理由は `[集計・保留]` とし、現段階では「実装済み・保留」と表現する
- Reheating
  - SA の停滞時に温度を上げる実装を試した履歴がある
  - 現行実装では使用しておらず、再検証項目になっている
  - 最終本文に載せる場合は、無効化した理由を実験ログで確認する `[集計・保留]`
- worker ごとの温度差
  - 温度倍率の仕組みはあるが、現行値は `0.0` で全 worker を同温度にしている
  - 高温 worker を混ぜる構成はチューニング候補として試されたが、現行設定には採用されていない
  - 採否理由の数値確認は `[集計・保留]`
- Bay-wise annealing / bay-wise preoptimization
  - ベイ単位の独立最適化を導入・撤回した履歴がある
  - `Z2` とベイ間移動を全体で扱いにくいため、現行では全体状態に対する探索を採用している
  - 理由の表現は履歴からの推測を含むため、本文掲載前に確認する `[要確認]`
- Kick、guided annealing、ray-based insertion
  - 導入後に revert または削除された履歴がある
  - 最終レポートでは、開発上重要だったものだけに絞って説明する
  - 具体的な比較結果は `[集計・保留]`
- 良好なブロック対を固定する探索
  - 時空間を効率的に使うブロック対を凸包面積などで評価する分析コードを作成した
  - 現行 solver には組み込まれておらず、将来案または検証段階として扱う
- EXIT 時刻の延長と操作順の直接探索
  - 現行解では常に `EXIT = ENTRY + processing_time` としている
  - 問題仕様上可能な、処理完了後もブロックを残す解は探索していない
  - ABBA 型と ABAB 型の滞在関係の変更や同日操作順の最適化は今後の課題とする

### 2.4 Further Improvement Plan

- Beam Large Reconstruct の再設計
  - 固定 base schedule に対する挿入候補を再利用する
  - ビーム内で追加した少数ブロックとの干渉だけを差分判定する
  - ベイ・向きごとの候補多様性を確保する
- 時刻表現の拡張
  - 最早 ENTRY だけでなく、元時刻、納期直前、禁止区間終了直後など複数時刻を候補化する
  - EXIT の延長を許し、ブロック間の滞在関係を変更できるようにする
  - 同日の EXIT/ENTRY 内部順序も探索対象にする
- Large Reconstruct の改善
  - ENTRY 時刻差ではなく滞在区間間の gap を距離に使う
  - tardy block を実際に妨害している blocker chain を除去対象にする
  - 探索進捗や停滞時間に応じて除去数とランダム性を増やす
  - target bay や time window を意識した seed 選択を追加する
- 高速化
  - base schedule に対する scan 結果と crane collision をより広く再利用する
  - scan-y と禁止時間区間処理の一時領域を再利用する
  - schedule 全体の目的関数と hash 再計算を差分更新へ置き換える
- 探索多様性
  - worker ごとに温度、近傍構成、制約の強さを変える portfolio 化を検討する
  - reheating または停滞検知型の大規模近傍を再検証する

## 3. Implementation Details

- ソフトウェア構成
  - コア solver は Rust 2024 edition で実装する
  - `geo` を多角形演算、`rayon` を並列化、`serde` / `serde_json` / `serde_yaml` を入出力とパラメータ管理に使用する
  - 乱数生成器には PCG64Mcg を使用する
  - Python wrapper が Rust executable を起動し、候補解の受信、実行可能性確認、最終解選択を担当する
- 解の内部表現
  - 各ブロックを `(block_id, bay_id, orientation, x, y, entry_time, exit_time)` で保持する
  - 目的関数計算時に総遅れ、ベイ別 workload、選好ペナルティを集計する
- 衝突判定
  - 各非凸レイヤーを凸多角形へ分解する
  - 向き対ごとに凸多角形の Minkowski 差を求め、整数相対座標上の衝突区間を rasterize する
  - クレーン制約の方向性を考慮し、A を移動する場合と B を移動する場合の両方向グリッドを構築する
  - 向き対の結果を atomic pointer を用いた lazy cache に保存し、worker 間で共有する
- 配置走査
  - 各 y 座標について、x 上の衝突状態変化をイベントとして生成する
  - counting sort で x イベントを並べ、同一状態が続く x 範囲を一括処理する
  - bitset 状の slot 集合を用いて、現在有効な禁止時間区間を管理する
  - 最初の実行可能時刻を求め、`x` は実行可能範囲の左端を候補とする
- 挿入ヒューリスティック
  - ベイは選好順、向きは bounding-box 面積順に調べる
  - y 座標は shuffle し、実行可能候補発見後も一定数を追加探索する
  - 候補は目的関数差、ENTRY 時刻、bounding-box 右端・上端で比較する
  - 最良スコアと同等の上位候補からランダムに選び、多様性を確保する
- Annealing engine
  - positive tardiness と zero tardiness で異なる温度 regime を使う
  - 線形、cosine、geometric の温度 schedule を設定可能にする
  - worker の局所状態、局所最良、共有最良、tabu list、近傍別統計を管理する
  - 時間比率と最大秒数の双方で各フェーズの時間を制御する
- 安全な出力
  - solver は一定間隔で候補解を標準出力へ stream する
  - wrapper は候補をスコア順に保持し、制限時間内で実行可能性を確認する
  - 最終候補だけに依存せず、途中の良好な実行可能解を利用できる
- パラメータ管理
  - アルゴリズムの主要パラメータは `src/params.rs` と `params/default.yaml` に集約する
  - tuning 用 YAML と suite 定義を用いて、温度、再構築順、ランダム性、時間配分を比較できる

- `[図・保留]` Large Reconstruct の remove-and-reinsert の模式図を作成する
